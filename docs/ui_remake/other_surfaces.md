## Placement, scaling, and data audit

- Menu scale is config::general_settings.menu_scale, clamped to 0.50–1.50 and constrained to display (src/ui/menu/layout.cpp:62-64). Menu uses first-use placement and transforms pointer/draw-list coordinates (src/ui/menu/menu.cpp:38-51,155-211).
- Overlay DPI comes from the target window and is clamped to 1.0–1.5 (src/ui/overlay/overlay.cpp:1949-1950); HUD sizing routes through ui_dpi_scale() (src/ui/overlay/hud.cpp:308) and display dimensions (:361-371). Compose Astral design-pixel scale with, not instead of, this policy.
- HUD panels are interactive/positionable; interactive is passed from the overlay frame (src/ui/overlay/overlay.cpp:604-612). Keep positions/scales tied to Vesta settings and keep live bindings for world ESP, spectators, events, notices, binds, trigger diagnostics, and bomb info.
- Original-goal settings missing complete menu coverage are present in schemas/serialization (src/config/visuals.hpp, src/config/misc.hpp, src/config/combat.hpp, src/config/settings.cpp): item ammo/count/color and shotgun/heavy filters; projectile default color; spectator-avatar preference; and additional general auto-stop options. Triggerbot Auto Stop UI writes the global misc.m_auto_stop settings (src/ui/menu/triggerbot_page.cpp:38); combat.triggerbot_autostop is a legacy mirror used to seed enabled state for older configs when misc.m_auto_stop is absent (src/config/settings.cpp:2223-2227). Only physical_fire and predictive_trigger in misc.m_auto_stop are serialized without a runtime consumer; these, plus spectator-avatar preference, need a behavior decision/implementation before being presented as working controls.

## Persistence outside the JSON profile inventory

These Vesta UI-related persisted values are outside the JSON config-key crosswalk and must not be mistaken for dropped bindings:

- **Lifecycle hotkeys:** menu and exit keys are stored separately in `hotkeys.cfg` under the active configs directory (`src/config/hotkeys.cpp:100-105,131-140`; UI editing in `src/ui/menu/guide_page.cpp`). They are not JSON profile keys.
- **First-run guide marker:** `guide.done` in the configs directory records whether the guide was completed/skipped; the “show again” action removes it (`src/config/first_run.hpp:6-9`, `src/config/first_run.cpp:13-18,31-40,68-76`). It is a marker file, not a profile setting.
- **Selected config folder:** stored in the Windows registry at `HKCU\Software\VestaUITest\ConfigFolder` (`src/platform/windows/user_settings.cpp:8-15,31-42`). This registry state is not part of the JSON profile inventory and remains fenced to the isolated test-data path.
