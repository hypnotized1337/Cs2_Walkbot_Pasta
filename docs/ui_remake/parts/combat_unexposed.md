# Combat saved fields without an old-menu control

The combat entries above are 37 serialized leaf paths. Config paths and defaults were checked against `config_keys.csv`; behavior classifications were checked against `src/config/settings.cpp`, `src/config/combat.hpp`, and the runtime consumers below. `combat_overrides[*]` represents the six weapon-group profiles. A `flash_threshold` and its `flash_threshold_percent` sibling serialize the same `legit_checks::flash_threshold` member, so the former is a compatibility alias, not another setting.

### Active user-facing fields: propose controls (17 schema leaves; 11 controls)

- `combat_global.aimbot_checks.flash_threshold_percent`, `combat_overrides[*].aimbot_checks.flash_threshold_percent`, `combat_global.triggerbot_checks.flash_threshold_percent`, and `combat_overrides[*].triggerbot_checks.flash_threshold_percent`: current `local_block_reason()` consumes this threshold to block combat when flash blindness reaches the configured percentage (`src/features/aimbot/aimbot_internal.cpp:81`). Decoder clamps it to `[0,100]` (`src/config/settings.cpp:511`). The legacy `flash_threshold` aliases are not separately proposed.
- `combat_global.triggerbot_revolver_pre_cock`, `combat_overrides[*].triggerbot_revolver_pre_cock`, `combat_global.triggerbot_revolver_release_margin_ms`, and `combat_overrides[*].triggerbot_revolver_release_margin_ms`: resolved into the active trigger profile and consumed by `update_revolver_pre_cock()` (`src/config/settings.cpp:2166-2169`, `src/features/aimbot/aimbot.cpp:420-452`). Release margin is clamped to `[1,60]` ms (`src/config/settings.cpp:225` and `347`). Pre-cock applies to the revolver path; per-group values only take effect when that profile is selected.
- `combat_global.penetration_crosshair`: enables the combat/aimbot penetration indicator (`src/config/settings.cpp:2171-2173`, `src/features/aimbot/aimbot.cpp:394-398`).
- The eight `combat_global.penetration_color_yes/no.{r,g,b,a}` leaves are two active RGBA values used to animate the combat/aimbot penetration indicator (`src/features/aimbot/aimbot_target.cpp:249-260`). Propose one color picker per serialized color object. These are **not** the separate ESP crosshair colors, which already have controls bound to `esp.m_crosshair.penetration_color_yes/no` (`src/ui/menu/visuals_page.cpp:500-501`). Decoder has no explicit numeric clamp for these RGBA channels, so leave the proposed picker range unspecified.

`parts/combat_proposed_controls.csv` records 11 proposed controls: four flash thresholds, four revolver settings, the penetration-indicator toggle, and two color pickers. The `condition` value is exactly `new control (no old UI)` and the old source-reference columns are blank.

### Legacy, derived, or inactive: do not add controls (20 schema leaves)

- `combat_global.aimbot_autowall`, `combat_overrides[*].aimbot_autowall`, `combat_global.aimbot_visible_only`, `combat_overrides[*].aimbot_visible_only`, `combat_global.triggerbot_autowall`, and `combat_overrides[*].triggerbot_autowall` are legacy fallback inputs. When nested `*_checks` is absent, deserialization converts visibility/autowall into `checks.walls` (`src/config/settings.cpp:152-160`, `292-300`); the runtime resolves wall behavior from checks rather than consuming these legacy members. The current “Only Visible” widget already controls `checks.walls`.
- `combat_global.aimbot_predictive` and `combat_overrides[*].aimbot_predictive` only seed nested `aimbot_prediction.enabled` when that object is absent. Resolved runtime prediction is overwritten from the nested profile (`src/config/settings.cpp:162-165`, `301-304`, `2140-2144`); the current Prediction widget controls the nested value.
- `combat_global.aimbot_recoil_sync` and `combat_overrides[*].aimbot_recoil_sync` are migration-only fallback values for nested `aimbot_rcs.enabled`; the resolved runtime flag is overwritten from the RCS profile (`src/config/settings.cpp:166-168`, `305-307`, `2143-2146`). The current RCS widget already controls that profile.
- `combat_global.triggerbot_autostop` and `combat_overrides[*].triggerbot_autostop` are legacy fields. If `misc.m_auto_stop` is missing, config decoding derives its `enabled` state from the combat fields (`src/config/settings.cpp:2222-2228`); the current Auto Stop control binds `misc.m_auto_stop.enabled`, so a second combat control would duplicate compatibility storage, not expose a separate active setting. This task does not duplicate the separate blocked `physical_fire` / `predictive_trigger` proposals.
- `combat_global.aimbot_fov_config.draw_target_point` and `combat_overrides[*].aimbot_fov_config.draw_target_point` are derived serialization outputs (`selection == target_distance`), and legacy input used to migrate FOV mode; they are not independent controls (`src/config/settings.cpp:626-629`, `641-675`). `combat_global.aimbot_fov_config.visualization` and its override counterpart are retained for older FOV indicator migration and are not exposed as independent current runtime controls.
- `combat_global.aimbot_checks.flash_threshold`, `combat_overrides[*].aimbot_checks.flash_threshold`, `combat_global.triggerbot_checks.flash_threshold`, and `combat_overrides[*].triggerbot_checks.flash_threshold` are legacy serialized aliases for the same percentage field. The decoder prefers `flash_threshold_percent`, converts old byte-scale values (including the historical `20 -> 85` special case), then clamps the shared member to `[0,100]` (`src/config/settings.cpp:490-512`). The active percentage field is proposed above; do not duplicate the alias.

No other combat keys from the generated no-menu list are omitted from this classification.
