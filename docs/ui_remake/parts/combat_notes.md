# Combat inventory notes

This inventory covers the existing Aimbot and Triggerbot menu calls and their nested popups. Source references are source-relative; `source_line` gives the UI call/helper line, and where useful identifies both caller and shared helper. A control's `min`/`max` are the arguments passed to its UI slider, never a claim about the decoder's clamp. Defaults in the CSV are current C++ aggregate/member defaults unless a condition or derived display value is stated. `configs/legit.cfg` is absent from this test fork, so the embedded-profile baseline could not be inspected; these are struct defaults, not a claim that the running app starts with them. Where the embedded file is absent, AGENTS.md says CMake falls back to an empty profile. Specifically: `combat_global` values come from `combat_profile::global_settings` and its nested structs; override values come from `combat_profile::group_overrides` and the same nested structs; `misc` values come from `general_settings` and its nested `auto_stop` struct. The serialized config roots are `combat_global`, `combat_overrides[*]` (wildcard expands to array indexes 0–5), and `misc`.

For the repeated override widgets, `combat_overrides[*].FIELD` denotes the same shared UI structure for indexes 0=Pistol, 1=SMG, 2=Rifle, 3=Shotgun, 4=Sniper, 5=Heavy. The same source page branch serves each selected group. Override controls are conditional on `use_global == false` and the corresponding global feature being enabled. `use_global` itself appears on each non-global tab for both pages.

## Conditional behavior and mappings

- Aimbot's global key is shown unless activation is Always On. Triggerbot's global key follows the same rule. Damage-override keys appear only when their popup's mode is not Always On. Per-group override pages do not expose enable, activation, or key controls.
- Global Triggerbot shows Reaction Time when seed type is Restricted or Unrestricted. When seed type is None it shows Hitchance, Auto Stop (including nested Stop Speed and Shoot Speed), and Shot Timing (five nested sliders). Group Triggerbot has the same seed-dependent Reaction Time/Hitchance and Shot Timing, but no Auto Stop popup or decision-debug toggle.
- The Visualization color popup has separate saturation/value, hue, and alpha drag areas; all edit the same serialized RGBA object (these are listed individually in the CSV).
- The override FOV row passes `group.aimbot_fov_config` but passes the global `aimbot_draw_fov` and `aimbot_fov_color` into the shared helper. Thus the override-tab Visualization/color control edits global keys; there are no per-group draw/color bindings in this UI call.
- “Only Visible” is a toggle over nested `checks.walls`: checked writes `block`, unchecked writes `penetration`. The config schema also has `ignore`, but the UI does not offer it; deserialization maps legacy `ignore` back to `penetration`.
- Trigger Auto Stop is the global `misc.m_auto_stop` object, not a per-weapon combat override. Legacy `triggerbot_autostop` fields are still serialized for global and group configs; decode migrates them into `misc.m_auto_stop.enabled` only when `misc.m_auto_stop` is absent. Other serialized auto-stop members `physical_fire` and `predictive_trigger` have no control in this combat page.
- Serialized legacy/parallel fields with no actual control in these audited pages include aimbot flat `aimbot_visible_only`/`aimbot_autowall`, `aimbot_predictive`/`aimbot_recoil_sync` mirrors, trigger `triggerbot_autowall`, `triggerbot_autostop`, `triggerbot_revolver_pre_cock`, and `triggerbot_revolver_release_margin_ms` (including override counterparts). The current controls bind to nested `*_checks`, `*_prediction`, and `aimbot_rcs` fields where applicable. No menu source location is invented for the absent controls. Triggerbot debug is a general `misc.trigger_debug_overlay` toggle, not a combat-profile field.
- FOV dynamic mode has one summary Max Radius slider and a second Max Radius slider under Advanced, both writing the same near-radius field. The selected Target profile uses `target_*`; Distance uses non-target fields. Fixed mode uses flat `aimbot_fov`. The color/picker is part of the Visualization row. `fov_settings.visualization` is retained for compatibility but is not directly controlled here.

## UI slider bounds vs JSON deserialization bounds

The CSV records UI bounds only. Important differences in `settings.cpp` deserialization are:

- `aimbot_multipoint_config.{head,body,limb}_scale`: UI `[0.05,0.95]`; JSON clamp `[0,0.95]`.
- Dynamic FOV: UI near/full-size distance `[0.5,10]`, far/min-size distance `[10,100]`, near radius `[2,45]`, far radius `[0.25,15]`; JSON bounds are broader/dependent (`near_distance` `[0.5,100]`, `far_distance` from `near+0.5` to `150`, `near_fov` `[0.25,180]`, and `far_fov` `[0.25,near_fov]`). These apply independently to Target and Distance fields. UI Fixed Radius is `[1,360]`; no corresponding clamp of flat `aimbot_fov` is present in combat deserialization.
- `triggerbot_outlier_chance`: UI `[0,25]`; JSON clamp `[0,100]` for global and overrides.
- `triggerbot_delay`, `triggerbot_hitchance`, `triggerbot_reaction_time`, and regular aimbot/triggerbot min damage sliders are UI-limited but are not independently clamped to those UI bounds by the current combat JSON decoder. Legacy `triggerbot_simple_delay` is clamped `[0,500]` during migration.
- Other combat nested fields with matching or dependent deserializer constraints include humanizer settings, prediction horizon, RCS fields, activation modes, override damage/key, trigger randomize/outlier delay/delay-after, multipoint preset, and FOV mode. `reaction_max_ms` JSON lower bound depends on `reaction_min_ms` even though its UI slider begins at 0.

The per-control config paths and widget source references are in `combat_controls.csv`; this notes file records only integration-relevant mapping and legacy behavior rather than duplicating the inventory.
